# Co-development

説明・議論・理解確認に使う時間も開発時間として扱う。通常の計画・レビュー・検証手順はそのまま使い、着手前と引き渡し前の2か所で止まる。hookによる強制や専用の進行コマンドは使わない。

## 着手前の確認（plan mode内）

1. Issueと関連コードを調べ、今回の変更の役割・目的・制約・完了条件を自分の言葉で示す。依頼時に宣言済みならそれを使い、計画で変わった点だけ言い直す。ユーザーの訂正を計画に反映する。
2. 難しい・影響が大きい・戻しにくい判断は、選択肢と理由を示して計画確定前に相談する。必要なら小さく実装・検証して理解を深める進め方を提案する。
3. 計画とレビューの反映後、重要な判断と期待する挙動を説明してミニクイズを1問出す。2問目以降は提案に留め、出すかはユーザーが選ぶ。まだ存在しないコードの細部や計画の暗記は問わない。
4. 回答に補足したら、同じターンでplan mode解除の承認を求めてよい。承認画面での拒否・質問には応じて再び止まる。解除の承認を着手の合意とし、正解や「理解しました」「LGTM」だけを着手の合図にしない。

## 実装中

- plan mode解除後の最初の作業として判断ログを作り、着手前の合意を書く。作成できなければ実装へ進まず、既存の権限・承認の経路で対処する。解決しなければ保存先をユーザーに相談する。
- 合意した範囲内の編集・検証ごとに許可を取り直さない。
- 想定外の制約や戻しにくい判断が現れたら、進める前に相談する。目的・範囲・完了条件・重要な方針が変わる場合は、変更点を言い直して計画と判断ログを更新し、その方針への明示的な合意を待って再開する。質問や訂正だけを再開の合図にしない。
- 相談せずに決めた戻しやすい判断も、理由とともに判断ログへ追記する。

判断ログは `/tmp/co-dev-<repo>-<branch>/decisions.md` に置く。`<branch>` の `/` は `-` に置き換え、ディレクトリは0700で作る。既にあれば読み、今回の作業のものか確かめてから追記する。別の作業のものだった場合や、途中で消えた・内容が欠けていた場合は、作り直す前にユーザーへ伝える。作業用の写しで、再起動などで消えうる。最終的な記録先は最終報告とPR本文。

```markdown
# <repo> <branch> (<Issue>)
## 着手前の合意
- <判断>: <理由>
## 変更・追加された判断
- <判断>: <分かった事実> → <変更内容と理由> [相談済み | agent単独]
```

## 引き渡し前の確認

5. 検証結果を合意した目的・完了条件と照合し、満たしたことと未確認事項を短く示す。重要な判断が実装のどこに反映され、どの検証で確かめられたかも短く共有する。
6. 判断ログのパスと「変更・追加された判断」を示す。agent単独の判断は、追認か見直しかをユーザーに委ねる。ミニクイズは出さず、質問を受け付ける。
7. そこでターンを終え、ユーザーが引き渡しに合意するまで完了扱い・commit・PR作成をしない。合意後の操作も既存の依頼・承認の範囲に従う。
8. 引き渡し時の追認・見直しを判断ログに反映し、最終報告には着手前の合意と最終的な判断を本文として残す。パスの提示だけで代用しない。PRを作るときは同じ内容をPR本文の判断セクションへ移す。

## 理解確認の作法

- 最初のミニクイズで、選択肢式／自由記述／自分の言葉で説明／「分からないので説明してほしい」から形式を選んでもらう。以後は同じ形式を使い、途中変更も受け付ける。
- 全体像から短く説明し、質問に応じて深める。文章・具体例・図・コード追跡から、内容に合う形式を使う。
- 回答に詰まったら、質問の曖昧さや説明不足を見直し、説明方法を変える。同じ問いを正解まで繰り返さず、AIの説明が誤っている可能性も検討する。
- 一問の正解で全体の理解を認定しない。根拠との一致・食い違い・未確認を示し、理解できたかはユーザーが判断する。
- 疲れや理解の難しさがあれば、範囲縮小・中断・保留を選べるようにする。確認を見送った内容は未確認として残す。

## 振り返り

引き渡しに合意した後、または中断・保留した時点で、次の下書きを出す。記録先はユーザーに確認し、投稿はユーザーが行うか、明示の承認後に行う。公開の場所に投稿する場合は、非公開のrepo名・Issue番号や業務に関わる情報を下書きに含めない。後続Issueへ自動では進まない。

```
- 対象: <repo>#<issue> / Claude Code or Codex / 選んだクイズ形式
- 役立ったこと:
- 負担だったこと:
- 停止点の過不足: 先走った / 不要に止まった / 適切
- 引き渡し前は共有だけで十分だったか:
- 次に変えたいこと:
```
